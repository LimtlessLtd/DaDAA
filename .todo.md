# DaDAA Project Plan (.todo.md)


- [x] **Phase 1: The Ears (Audio & Transcription)**
  - [x] Establish Node.js Discord bot voice connection.
  - [x] Route voice streams to the local Python transcription server.
  - [x] Output clean, speaker-labeled text in real time.


- [x] **Phase 2: The Brain (Context & Relevancy)**
  - [x] Build an OOC (Out-Of-Character) filter to ignore table talk and jokes.
  - [x] Let the AI DM invent and persist its own world knowledge (NPCs, locations, items, quests, lore) as players explore, instead of importing from an external VTT.
  - [x] Implement short-term memory Summarization to prevent AI context bloat.
  - [x] Design an "importance filter" so the AI only flags critical triggers.
  - [x] Implement player character log, associate which users in Discord control which characters, and let the AI log character development, traumatic experiences, notable NPCs, and major plot events in their life.
  - [x] Implement a "current event" feature which will guide The Brain on what the next event might look like based on previously archived events and the summaries for each one.


- [x] **Phase 3: The Voice (In-Character Speech & Prompts)**
  - [x] Set up Text-to-Speech (TTS) so the AI can speak directly back into the Discord channel.
  - [x] Implement in-character narrative delivery (DM persona, tone, pacing).
  - [x] Between the DM reading the world introduction aloud and announcing the opening event, have each player introduce themselves and their character (name, brief description, what they're doing as the scene opens) before Session 1 begins, and link this to the Character Mapping functionality e.g. discord user -> player is determined automatically from this introduction.
  - [x] Code check-trigger logic (e.g., the AI prompts: "Roll a DC 12 Athletics check") and integrates with Discord dice rolling bots like Dice Maiden.
  - [x] Build a success/failure outcome system to handle rolls and narrative results (including critical success/failure on natural 20s/1s).
  - [x] Implement consequences for success and failure outcomes (narrative-level - the DM must narrate a concrete consequence; mechanical consequences like HP/inventory tracking are still Phase 4).
  - [x] Implement RAG database instead of text files.


- [x] **Phase 4: The Canvas (Visuals & Living Events)**
  - [x] Auto-generate an NPC portrait the first time a new NPC entity is invented (the `worldEntities` path), and persist it alongside the entity so the same NPC keeps the same portrait for the rest of the campaign - the same "locked in on first use" pattern already used for TTS voices.
  - [x] Surface portraits in the dashboard's World Entities panel next to each NPC.
  - [x] Introduce "background events" alongside the "current event" mechanic: "background events" should support multiple concurrent threads that can escalate, intersect, or resolve independently of each other instead of forcing everything through the "current event" mechanic. The "current event" mechanic should purely be about the current situation players find themselves in. "Background events" should escalate, intersect, or resolve very occassionally and it could be that players are not even aware of the "background events" occurring.
  - [x] Let new events (background and/or current) tie into specific already-established NPCs/locations/lore instead of always generating fully fresh ones, so recurring threats/threads feel connected rather than one-off.
  - [x] Generate an image of the active event on every change to it (`eventStatus` is anything other than `stable` - evolved, escalated, or resolved), regardless of whether the change was a success or failure, so the visual always reflects the current `currentState` rather than the original `description`.
  - [x] Post the active event's image to the Discord text channel via the bot whenever it's (re)generated, so the table gets a visual alongside the narration instead of it being dashboard-only.
  - [x] When an NPC speaks (a `dialogue` segment with a non-narrator speaker), post that line to the Discord text channel alongside the NPC's portrait, so players get a face to match the voice.
  - [x] Rate-limit image generation app-wide via a `config.json` setting (e.g. `ImageGenConfig.minIntervalMs`, defaulting to 3 minutes) - a single shared cooldown/queue covering NPC portraits and event images together, not a separate limit per feature, so a burst of new NPCs or rapid event changes can't hammer the image generator all at once, and the interval can be retuned without a code change.
  - [x] Improve image generation and accuracy: Generate images based on detailed descriptions of current events/NPCs/locations/items/quests/lore/encounters and make sure the related entity is updated in the world entities tab on the dashboard.
  - [x] Image & Description posted to discord: Whenever an image is posted to the discord it should be accompanied by the narration/speech and description used to generate that image. Can include emojis for better immersion.
  - [x] Restrict image generation to only latest event, dont generate a new image if nothing has changed.
